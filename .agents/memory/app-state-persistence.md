name: App state persistence
description: How My Day AI persists tasks/projects/captures/preferences to the database instead of localStorage
---

## Architecture
- Database table: `app_state` (id serial PK, state jsonb, updated_at timestamp)
- Single row with id=1 stores the entire AppState as JSON blob
- API: `GET /api/app/state` — returns row or seeds on first visit; `PUT /api/app/state` — upserts

## Frontend
- `useGetAppState` / `useSaveAppState` hooks from `@workspace/api-client-react` (generated by orval)
- `useAppState()` custom hook is called inside `AppInner` (which is inside `QueryClientProvider`), NOT in `App` directly
- State changes are debounced 600ms before saving to server
- One-time localStorage migration: checks `my-day-ai-migrated-v1` flag; if absent, reads `my-day-ai-state-v1` from localStorage, PUTs it, sets flag

**Why:** Single-blob approach keeps frontend state management identical to the old localStorage pattern — minimal code change, correct behavior.

**How to apply:** If adding new state fields, they just flow through the JSONB blob automatically. No schema migration needed unless querying individual fields.
